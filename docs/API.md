# API Reference

Base URL for local development: `http://localhost:4000/api`.

Protected endpoints require `Authorization: Bearer <token>`. Login tokens expire after eight hours. JSON errors use `{ "error": "..." }`.

## Health and authentication

| Method | Path | Access | Purpose |
| --- | --- | --- | --- |
| `GET` | `/health` | Public | Check API and database connectivity |
| `POST` | `/auth/login` | Public | Sign in with `{ "identifier": "...", "password": "..." }` |
| `POST` | `/auth/register` | Public, rate-limited | Create a student account; staff/admin roles cannot self-register |
| `GET` | `/auth/me` | Signed in | Return the current account |

Registration accepts `studentId`, `fullName`, `email`, `password`, `departmentId`, `year`, `section`, and optional `phone`. It creates only a student account, normalizes the ID/email, hashes the password, and returns a signed-in session. Duplicate student IDs/emails return `409`. This version does not yet verify email ownership or enrollment against an official student roster.

Successful login returns `{ "token": "...", "user": { ... } }`.

## Complaints

| Method | Path | Access | Purpose |
| --- | --- | --- | --- |
| `GET` | `/complaints` | Signed in | List visible complaints; accepts `search` and `status` query parameters |
| `GET` | `/complaints/export` | Admin | Download all complaints in CSV spreadsheet format |
| `POST` | `/complaints` | Student | Submit a complaint |
| `GET` | `/complaints/:id` | Owner, assignee, or admin | Read details and chronological history |
| `PATCH` | `/complaints/:id/assign` | Admin | Assign `{ "staffId": 1 }` |
| `PATCH` | `/complaints/:id/status` | Admin, assigned staff, or student (closure) | Change status with `{ "status": "In Progress", "remarks": "..." }`. Students can close their resolved complaints with feedback. |

Student submissions accept `categoryId`, `title` (5-180 characters), `description` (20-5000 characters), and `priority` (`Low`, `Medium`, `High`, or `Critical`). The student's department is taken from their account. Complaint IDs are generated by the API.

Valid statuses are `Submitted`, `Under Review`, `Assigned`, `In Progress`, `Waiting for Student`, `Resolved`, `Closed`, and `Rejected`.

## Reference data and dashboards

| Method | Path | Access | Purpose |
| --- | --- | --- | --- |
| `GET` | `/dashboard` | Signed in | Role-scoped live counts |
| `GET` | `/categories` | Signed in | Active complaint categories |
| `GET` | `/departments` | Public | Active departments offered during student signup |
| `GET` | `/staff` | Admin | Active staff available for assignment |
| `GET` | `/notifications` | Signed in | Current user's recent notifications |

Students only see their own complaints. Staff only see cases assigned to them. Administrators can see all complaints. Attempts to read an inaccessible complaint return `404` to avoid disclosing its existence.
